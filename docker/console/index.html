dolt-megasamples

The 21 sample databases of sql-megasamples, loaded into Dolt, DoltgreSQL and DoltLite and served here beside their consoles, so you can open real data in each versioned engine with a tool of your own. They are also the subject of an experiment -- what does a Dolt engine cost against the database it stands in for, in disk, time and memory? Loaded once and committed once, as served here, the stores are 0.29× MySQL's, 0.35× PostgreSQL's, 1.39× SQLite's (over the databases each pair has every load for: DoltLite 20 of 21); a commit per row costs far more. On Dolt, a commit per row costs 7× to 1524× the one-commit store, measured on 21 databases: history is the expensive part, not the rows. README.md tells the story and REPORT.md carries every number.

Consoles, by what they can open

CloudBeaverDolt and DoltgreSQLOpen as a guest; both accounts of both engines are in the sidebar. DbGateDolt and DoltgreSQLFour connections are preconfigured in the sidebar. Dolt WorkbenchDolt, DoltgreSQL and every DoltLite fileBranches, commits and diffs — the part the others cannot show. Both accounts on both servers and each DoltLite file are saved connections: pick one from its list (it keeps one current connection at a time). AdminerDolt and DoltgreSQLIts login form remains: system MySQL, server dolt — or system PostgreSQL, server doltgres — with either account. phpMyAdminDolt onlySigned in already; the server menu switches account.

Connect with your own tool

Dolt 2.3.2 (MySQL protocol)

address127.0.0.1 port 3307
accountsdemo / demo (read only) · admin / admin (all privileges) · root / root
clientmysql -h 127.0.0.1 -P 3307 -u demo -pdemo sakila
URLmysql://demo:demo@127.0.0.1:3307/sakila
JDBCjdbc:mysql://127.0.0.1:3307/sakila
version controldolt_log, dolt_diff and the rest are tables and procedures: SELECT * FROM dolt_log; CALL dolt_commit('-Am', '...')

DoltgreSQL 1.3.2 (PostgreSQL protocol)

address127.0.0.1 port 5433
accountsdemo / demo (reads every table) · admin / admin (superuser) · postgres / doltsamples
privilegesenforced from 1.3.2 (this is 1.3.2): demo is refused CREATE DATABASE and DROP DATABASE; a role can still grant itself CREATEDB, which PostgreSQL refuses
clientPGPASSWORD=demo psql -h 127.0.0.1 -p 5433 -U demo -d sakila
URLpostgresql://demo:demo@127.0.0.1:5433/sakila
JDBCjdbc:postgresql://127.0.0.1:5433/sakila
version controlSELECT * FROM dolt_log; SELECT dolt_commit('-Am', '...') — SQL only, there is no CLI
noteone database per dataset, each its own repository; some objects were not carried — the report says which

DoltLite v0.50.10 (files)

files/data/{database}.doltlite inside the doltsamples-doltlite container; no accounts, no server
opendocker exec -it doltsamples-doltlite doltlite /data/sakila.doltlite
copy one outdocker cp doltsamples-doltlite:/data/sakila.doltlite .
version controlSELECT * FROM dolt_log; SELECT dolt_commit('-Am', '...'); VACUUM is garbage collection
consoleDolt Workbench opens each file through its own DoltLite: pick the "DoltLite <database>" connection
notea DoltLite file is not SQLite pages: sqlite3, Adminer, DbGate and CloudBeaver cannot open it; the doltlite shell, libdoltlite and the Workbench can. One durable writer at a time.
