dolt-megasamples

The sql-megasamples databases loaded into Dolt — and into DoltgreSQL and DoltLite — with what each costs on disk beside the engine it mirrors. The Dolt column is the one-commit load, 0.29× MySQL across 21 databases. Committing one row at a time instead costs 7× to 1524× as much, measured on 21 of them — history is the expensive part, not the rows. See REPORT.md. The same rows were also loaded into PostgreSQL and DoltgreSQL, and into SQLite and DoltLite, each pair from its own dump, one commit per database; those sizes are in the last columns.

Consoles, by what they can open

CloudBeaverDolt and DoltgreSQLOpen as a guest; both accounts of both engines are in the sidebar. DbGateDolt and DoltgreSQLFour connections are preconfigured in the sidebar. Dolt WorkbenchDolt, DoltgreSQL and every DoltLite fileBranches, commits and diffs — the part the others cannot show. Both accounts on both servers and each DoltLite file are saved connections: pick one from its list (it keeps one current connection at a time). AdminerDolt and DoltgreSQLIts login form remains: system MySQL, server dolt — or system PostgreSQL, server doltgres — with either account. phpMyAdminDolt onlySigned in already; the server menu switches account.

files/data/{database}.doltlite inside the doltsamples-doltlite container; no accounts, no server
opendocker exec -it doltsamples-doltlite doltlite /data/sakila.doltlite
copy one outdocker cp doltsamples-doltlite:/data/sakila.doltlite .
version controlSELECT * FROM dolt_log; SELECT dolt_commit('-Am', '...'); VACUUM is garbage collection

notea DoltLite file is not SQLite pages: sqlite3, Adminer, DbGate and CloudBeaver cannot open it; the doltlite shell, libdoltlite and the Workbench can. One durable writer at a time.
